## Environment

- **venv:** the old `.venv` could not be moved. Its `pyvenv.cfg`, launchers and the
  editable-install file `eureka_2026_kt.pth` hold absolute paths under `D:\EUREKA-2026`.
  Once `tools\` had moved, its `python.exe` failed with exit 103 ("did not find
  executable"). The new `.venv` was built by `scripts/setup.ps1` from the unchanged
  `uv.lock`: no relock, the same 66 distributions at the same versions, the project
  itself installed editable, and the kernelspec `eureka-2026` reinstalled.
- **Managed Python:** `tools\python` moved as is. uv's minor-version junction
  `cpython-3.14-windows-x86_64-none` pointed at the old absolute path; only the link
  was replaced, pointing at the moved `cpython-3.14.7-windows-x86_64-none`.
- **Non-ASCII root:** the new path contains "É". `project.env` is now UTF-8 and
  `scripts/_common.ps1` reads it as UTF-8, because PowerShell 5.1 would read it as
  Windows-1252. The `.ps1` files stay ASCII. One test decoded `pip cache dir` output as
  cp1252 and failed on the new path; it now uses UTF-8 on both sides.
